# Valhalla 路由引擎完整学习路线图
> Valhalla：C++编写、基于OSM的开源多模式路由引擎，支持驾车/骑行/步行/公交、等时圈、矩阵、地图匹配、TSP路径优化，瓦片式图存储，Mapbox Directions底层引擎。
> 前置基础：C++17、CMake、Boost、Protobuf、OSM基础、图论(Dijkstra/A*)、GIS基础；对比参考OSRM，适合做离线私有部署、园区/城市定制路由。

整体分为5个阶段：**快速上手 → 部署与数据流水线 → 架构与源码阅读 → 二次开发定制 → 生产调优与实战项目**。

## 阶段1：快速上手（1‑2天，会用API，建立感性认知）
目标：不用编译源码，理解能力边界，熟悉全部接口能力。
1. 概念预习
    - OSM PBF数据格式、道路tag含义；路由基本概念：cost代价、edge/vertex、turn‑cost转弯代价、等时圈isochrone、OD矩阵、地图匹配map‑matching。
    - 对比OSRM：Valhalla优势：多模式原生、瓦片分层图、动态costing、地图匹配；劣势：内存占用更高。
2. 体验官方Demo：https://valhalla.openstreetmap.de
3. Docker快速跑实例（不编译源码）
    ```bash
    docker run -d -p 8002:8002 valhalla/valhalla
    ```
    调用接口：`/route`、`/isochrone`、`/matrix`、`/map‑matching`、`/locate`、`/height`，通读API文档。
4. 学习API请求JSON参数
    - costing模型：auto/bicycle/pedestrian/multimodal；costing_options调参（避高速、避渡轮、坡度权重）。
    - 看懂返回：shape、maneuver导航指令、time/distance。
5. 练习：pyvalhalla快速调用，python做简单脚本实验。

**输出产物**：写脚本完成路径规划、等时圈、OD矩阵；清楚每个接口能干什么。

## 阶段2：本地编译、数据流水线（3‑5天，能自己构建瓦片，部署私有服务）
> 核心命令：`valhalla_build_tiles`（Mjolnir模块），把osm.pbf编译成valhalla瓦片图库。
### 2.1 源码编译
1. 源码克隆：`git clone --recurse‑submodules https://github.com/valhalla/valhalla.git`
2. CMake关键选项：
    - `‑DENABLE_DATA_TOOLS=ON`：构建瓦片工具（必须）
    - `‑DENABLE_SERVICES=ON`：http服务
    - `‑DENABLE_PYTHON_BINDINGS=ON`：pyvalhalla绑定
3. 依赖：boost、protobuf、lua5.2、geos、spatialite、lz4、prime‑server。
> 坑：Ubuntu推荐用官方ppa；mac/linux优先docker编译调试；编译失败重点看子模块是否完整。

### 2.2 完整数据构建流程
1. 获取OSM PBF：geofabrik下载区域数据，可osmconvert裁剪小区域做测试。
2. 构建admin数据库（行政区，处理道路行驶方向、环岛、边界惩罚，强烈建议）。
3. （可选）Skadi高程数据，给骑行/步行做坡度代价。
4. `valhalla_build_config`生成valhalla.json配置文件。
5. `valhalla_build_tiles`生成瓦片库 valhalla_tiles.tar。
6. 启动服务：`valhalla_service valhalla.json 8002`。
7. 验证：请求route接口，确认路由正常。

### 2.3 重要工具掌握
- `valhalla_service`：http服务；也支持一次性命令行模式不启动http服务。
- `valhalla_build_admins`：构建行政区库。
- `valhalla_build_elevation`：高程数据。
- `valhalla_export_edges`：导出图边，用于调试图构建结果。

**练习任务**：
1. 小区域（城市级别）完整从pbf到瓦片、跑通服务。
2. 修改valhalla.json，调整缓存大小、瓦片路径。
3. 理解：瓦片分层存储，不同缩放层级，粗粒度高层用于长距离路径。

## 阶段3：核心架构与源码阅读（1‑2周，读懂模块分工，理解路由完整流程）
Valhalla八大核心库，每个库对应一个文件夹，北欧神话命名体系：

|模块|目录|作用|
|---|---|---|
|Midgard|midgard|基础GIS几何库：距离、交点、多边形、坐标转换|
|Baldr|baldr|瓦片图存储结构，edge/node数据结构，瓦片缓存|
|Mjolnir|mjolnir|**数据预处理**：OSM‑PBF → 瓦片图，tag解析、转弯代价、图构建|
|Loki|loki|**定位**：经纬度匹配到图上edge，候选边查找|
|Sif|sif|**代价模型** DynamicCost，各种交通模式cost计算，权重配置|
|Thor|thor|**路径搜索**：双向A*、单向A*，多模路径；核心寻路算法|
|Meili|meili|地图匹配，GPS轨迹对齐道路网|
|Odin|odin|路径生成导航maneuver、转向提示、叙事文本|

### 完整路由调用链路（route请求）
`HTTP请求 → Loki(找候选边) → Sif(代价模型) → Thor(A*寻路得到路径边序列) → Odin(生成导航指令) → JSON输出`。

### 源码阅读顺序建议
1. **Midgard**：几何工具，看懂基础GIS工具函数。
2. **Baldr**：看数据结构 `baldr/graphid.h`、`edgeinfo.h`，瓦片存储组织。
3. **Sif/DynamicCost**：理解代价如何计算，不同交通工具怎么给边打cost。
4. **Loki**：点匹配到道路逻辑。
5. **Thor**：寻路算法 BidirectionalAStar，路径生成；重点看`thor/pathalgorithm.h`。
6. **Mjolnir**：OSM导入逻辑，tag解析，图构建；理解osm标签如何映射为图属性。
7. Meili地图匹配、Odin导航指令。

> 官方文档：https://valhalla.github.io/valhalla/route_overview/ 路由计算总览，必看。

## 阶段4：二次开发与定制（重点，适合项目开发）
### 4.1 常见定制方向
1. **自定义costing代价模型（最常用）**
    在`sif`模块新增Cost，实现DynamicCost接口；自定义道路惩罚、优先路线，适合园区、厂区、机器人场景。
2. 扩展OSM tag解析（Mjolnir）：私有tag导入图属性。
3. 修改Loki点匹配逻辑：增强GPS定位匹配，适配机器人RTK点。
4. Meili地图匹配调参：轨迹匹配参数，低频率GPS轨迹。
5. Odin导航指令定制：自定义转向提示文本。
6. 扩展接口：新增http接口，prime‑server做http服务层。
7. 离线嵌入式：编译静态库，剥离http服务，直接调用C++ Actor接口做本地计算，不启服务。

### 4.2 两种集成模式
1. HTTP服务模式：部署服务，网络调用（业务系统）。
2. 库模式（Actor）：C++直接调用Actor，加载瓦片，进程内计算，适合机器人、离线程序，不开启8002端口。
```cpp
// Actor 是C++直接调用入口，pyvalhalla底层也是封装Actor
valhalla::actor::Actor actor(config);
actor.route(request_json);
```

### 4.3 调试技巧
1. 使用`/locate`接口查看某个点匹配到的edge信息。
2. `/expand`接口，看算法搜索扩展的图节点，调试寻路。
3. 开启日志，打印cost、turn‑cost。
4. 单元测试：源码自带大量test用例。

## 阶段5：生产调优、踩坑、实战项目（工程落地）
### 性能调优
1. 内存：瓦片缓存配置，大区域内存消耗；tar包vs目录瓦片。
2. 并发：prime‑server线程数；大请求矩阵/isochrone压力。
3. 构建瓦片调优：大星球planet构建机器配置。
4. 高程Skadi：开启高程会增加构建耗时和内存。

### 高频坑点
1. OSM数据质量：错误tag导致路由绕路、断头路；admin数据库缺失环岛出错。
2. 瓦片版本和程序版本必须严格匹配，版本不兼容直接报错。
3. turn_cost转弯代价，复杂路口路由异常。
4. 国内OSM道路数据不全，需要补充自定义路网。

### 实战项目选题（适合你做机器人/园区GIS）
1. 园区私有路网：自定义geojson/自定义OSM，导入valhalla，机器人路径规划。
2. RTK轨迹地图匹配：Meili做GPS轨迹匹配，输出行驶路线。
3. 离线C++程序，不启动http服务，进程内Actor做路径计算。
4. 对比OSRM和Valhalla在工业园区数据的性能差异。

## 与OSRM对比快速参考
| |Valhalla|OSRM|
|---|---|---|
|开发语言|C++|C++|
|图存储|分层瓦片tar包|单份文件|
|多模式|原生支持驾车/骑行/步行/公交|支持，公交较弱|
|代价模型|运行时动态costing，灵活|编译期为主|
|地图匹配|Meili原生|支持|
|等时圈、TSP优化|原生支持|需要额外工具|
|适合场景|私有部署、机器人、多模式、离线库调用|高性能单模式，互联网服务|
