# 如何计算地球表面两点间距离
这段话是地图导航和地理信息系统（GIS）领域关于**“如何计算地球表面两点间距离”**的一篇极具工程实战价值的技术总结。
它对比了除了你之前知道的 Haversine（半正矢公式） 之外的另外两种替代方案：球面余弦定律（Spherical Law of Cosines） 和 等距圆柱投影近似（Equirectangular Approximation，即平地勾股定理）。
下面为你逐段进行硬核拆解和深度翻译：

## 第一部分：球面余弦定律（Spherical Law of Cosines）


1. 核心理论与现代计算机的精度红利

• 原文大意：过去在老旧的计算机或计算器上，大家更倾向于用 Haversine 公式，因为传统的球面余弦公式在计算“极小距离（比如几米）”时会因为浮点数精度不够而产生巨大的舍入误差（称为病态条件）。
• 现代颠覆：但现在，JavaScript 门语言以及几乎所有现代 CPU 默认都使用 IEEE 754 双精度 64 位浮点数，能够提供 15 位的有效数字精度。在这项技术红利下，简单的“球面余弦定律”即使在计算地球表面小到几米的距离时，结果依然非常稳定和精准。
• (注：公式内部做了一些变向微调，让我们能直接带入“纬度”，而不需要先换算成“余纬/极角”。)

2. 为什么选它？（一行代码搞定）

• 原文大意：这使得它成为了 Haversine 的完美“一行代码平替方案”。你可以根据你的编程语言、处理器性能或代码上下文来选择。
• 代码实现：
	• 公式：\(d = \arccos( \sin\phi_1 \cdot \sin\phi_2 + \cos\phi_1 \cdot \cos\phi_2 \cdot \cos\Delta\lambda ) \cdot R\)
	• JavaScript 落地：javascript
const φ1 = lat1 * Math.PI/180, φ2 = lat2 * Math.PI/180, Δλ = (lon2-lon1) * Math.PI/180, R = 6371e3;
const d = Math.acos( Math.sin(φ1)*Math.sin(φ2) + Math.cos(φ1)*Math.cos(φ2) * Math.cos(Δλ) ) * R;
请谨慎使用此类代码。
• 性能实测评语：虽然它代码只有一行，看起来最简单，但在作者的实际性能测试中，它的运行速度其实比 Haversine 还要稍微慢一点点（因为 acos、sin、cos 组合在底层的 CPU 指令集消耗略高）。

## 第二部分：等距圆柱投影近似（极速平地近似法）


1. 什么时候用它？（极致追求性能）

• 原文大意：如果你的代码运行在算力极度受限的环境（如单片机、车载低端 MCU），或者你在处理海量点云数据，性能（Speed）是第一死穴，而精度不需要那么极端，那么只要两点之间的距离很近，我们就可以把地球表面踩平，直接用勾股定理来算。

2. 数学原理与代码

它把经纬度投影成了一个平面：
• \(y\) 轴：直接就是纬度差（因为地球上纬度一线的物理距离是均匀的）。
• \(x\) 轴：经度差乘以当前平均纬度的余弦值 \(\cos\phi_m\)（用来补偿由于地球变圆导致的经线向两极收缩的误差）。
• JavaScript 落地：javascript
const x = (λ2-λ1) * Math.cos((φ1+φ2)/2);
const y = (φ2-φ1);
const d = Math.sqrt(x*x + y*y) * R; // 完美的勾股定理
请谨慎使用此类代码。

3. 恐怖的性能优势

• 算力对比：
	• Haversine：需要调用 7 次三角函数 + 2 次开方 (sqrt)。
	• 余弦定律：需要调用 6 次三角函数 + 1 次反三角函数 (acos)。
	• 平地近似法：只需要 1 次三角函数（cos）+ 1 次开方（sqrt）！
• 精度代价：如果沿着同一条经线（南北方向）计算，它完全没有误差；如果是其他方向，误差大小取决于两点间的距离和所处的纬度。但只要距离短，这个误差和“把地球当成完美球体本身带来的系统误差”相比，小到可以忽略不计。

## 第三部分：极坐标平地公式（另一种平地替代）

• 原文大意：作者提到还有另外一种利用“极坐标（Polar Coordinates）”的平地公式，使用余纬（\(\theta = \pi/2 - \phi\)）带入余弦定理变体：\(d = R \cdot \sqrt{\theta_1^2 + \theta_2^2 - 2\theta_1\theta_2\cos\Delta\lambda}\)。但他本人没有对这个公式的精度进行具体横向对比。

💡 总结：你在开发（如 Valhalla 路由引擎）时该怎么选？

这段技术文档为你指明了工程落地的选型指南：
1. 如果你在做跨国、跨城市的长距离路线规划（如 Valhalla 的大干线计算）：
	• 用 Haversine 或 球面余弦定律。两者的精度在现代 64 位计算机上已经完全一致，由于 Haversine 里的机器指令可能稍快，维持原版 haversine 即可。
2. 如果你在做高频、局部的距离判断（如自动驾驶车辆在 100 米内判断是否压到车道线、或者在密集点云里找最近的障碍物点）：
	• 果断选择 Equirectangular approximation（平地近似法）！因为它能帮你省掉极其昂贵的 CPU 三角函数算力，让你的算法运行速度暴增数倍。
